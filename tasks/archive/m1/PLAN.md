## Synthetic data rules

Every venue name starts with "DEMO" or is marked `isSynthetic: true`. Prices are fictional INR paise. Pages render a visible "SYNTHETIC DATA - MOCK MODE" badge. No real venue names, photos, addresses or payment provider keys.

## Commands (exact contract)

| Command | Behaviour in M1 |
| --- | --- |
| `pnpm install --frozen-lockfile` | Installs all workspaces from the committed lockfile |
| `pnpm dev:web` | Starts Next.js dev server on port 3000 |
| `pnpm dev:mobile` | Starts Expo dev server (`expo start`) |
| `pnpm dev:worker` | Runs worker in mock queue mode |
| `pnpm db:start` | `supabase start` (requires Docker) |
| `pnpm db:reset` | `supabase db reset` against the local stack only |
| `pnpm lint` | ESLint across workspaces |
| `pnpm typecheck` | `tsc --noEmit` per package |
| `pnpm test:unit` | Vitest: contracts, domain pricing, design-token contrast, api-client, worker |
| `pnpm test:integration` | Vitest placeholder; reports todo until M2 real database tests exist |
| `pnpm test:e2e` | Playwright smoke test against a built web app |
| `pnpm test:mobile` | `expo export` bundle compile for Android and iOS; not a device test |
| `pnpm build` | Next.js build, worker tsc build, Expo export |

## Completion checks

1. `pnpm install --frozen-lockfile` succeeds from the committed lockfile.
2. `pnpm lint`, `pnpm typecheck`, `pnpm test:unit`, `pnpm build` exit 0.
3. `pnpm dev:web` serves `/`, `/venues/demo-...`, `/partner`, `/staff`, `/admin`, `/api/v1/health`, `/api/v1/venues` (HTTP 200 checked with curl); screens inspected via screenshot.
4. `pnpm test:e2e` passes.
5. `pnpm dev:worker` logs heartbeats and stops on SIGINT.
6. `pnpm db:start` works if Docker daemon is running; otherwise recorded as blocked with the exact error.
7. `pnpm test:mobile` exports Android and iOS bundles. Android device/emulator run is attempted only if an emulator exists; iOS native build is recorded as unavailable on Windows.
8. `scripts/check-secrets.mjs` passes and `.env` files are ignored.

## Dependencies and risks

- Docker daemon must be running for `db:start`.
- Android SDK location is in `%LOCALAPPDATA%\Android\Sdk`; `ANDROID_HOME` is not set in this shell.
- iOS: Windows cannot build or run an iOS app. Requires an authorised EAS build or macOS runner and an iPhone; not available here.
- Playwright browsers must be installed; download may be slow.
