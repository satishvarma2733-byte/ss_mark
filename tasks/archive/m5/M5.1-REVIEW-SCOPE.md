# M5.1 independent review - scope for a fresh reviewer

Required by CLAUDE.md and docs/06 M5.1 before release. The reviewer must not be the session that wrote the code.
Options: a human reviewer, a new Claude Code session given only this file, or `/code-review ultra` (user-triggered,
billed, multi-agent cloud review). Read-only; findings go to `tasks/current/M5.1-FINDINGS.md` with evidence
(file:line, failing scenario). Critical/high findings block the release candidate until fixed and retested.

## What the system promises (CLAUDE.md "non-negotiable behavior")

Database-enforced exclusive inventory; trusted payment verification; safe retries; no late-payment resurrection;
explicit refund state; immutable price/policy snapshots; tenant-scoped server permissions; audited sensitive actions.
Clients never set trusted price, role, paid status, settlement or availability.

## Where the rules live

All writes go through SECURITY DEFINER `app.*` functions (search_path ''), called by the Next.js API with role
switching (`packages/db/src/index.ts`: asAnon / asUser / asWorker). RLS is forced on every public table.
